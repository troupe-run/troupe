# Design

## Context

See proposal.md, Why. The generated files come from the OpenSpec CLI's Claude Code integration. `openspec update`
rewrites every file it owns for the tools configured in the project. Here that is Claude Code only, with the six
default workflows. The CLI installed locally is Homebrew's 1.14.2 (`/opt/homebrew/Cellar/openspec/1.14.2`), and
Homebrew doesn't have 1.14.3 yet. npm does (`@fission-ai/openspec@1.14.3`, published 2026-10-17).

## Goals / Non-Goals

**Goals:**
- The 9 generated files are exactly what `openspec update` 1.14.3 writes, with no hand edits.
- The repository ignores `.claude/settings.local.json` without relying on anyone's personal git config.

**Non-Goals:**
- Adding the 6 optional workflows (`new`, `continue`, `ff`, `bulk-archive`, `verify`, `onboard`) that the CLI
  offers. That is a profile change, not a version bump.
- Skipping `.claude/**` in `scripts/check-paths.toml`. It would save the full check on future regenerations, but
  it's a separate decision about the declaration (spec: quality-check).
- Changing how OpenSpec is installed on the machine. Homebrew's 1.14.2 stays until Homebrew ships 1.14.3 (owner,
  2026-10-18).

## Decisions

**D1. Use 1.14.3, run through npx at the exact version.** The plan first pinned 1.14.2, the version the issue named,
to match the website. On 2026-10-18 the owner chose 1.14.3, the latest release, instead. The regeneration runs
`npx -y @fission-ai/openspec@1.14.3 update`. An exact version, never `@latest`, so the output can be reproduced. The
alternative was installing 1.14.3 globally from npm. The owner declined it, because a second install would shadow or
be shadowed by Homebrew's, depending on `PATH` order.

**D2. `skip_specs: true`.** No troupe requirement changes. Writing a requirement about generated tooling files only
to pass validation would invent one. The guarantee that the files match the CLI is checked here by regenerating
them and comparing (tasks 1.2 to 1.4), not by a spec.

**D3. Ignore the exact path `.claude/settings.local.json`.** It's the same line as the website's `.gitignore`, so
the repositories stay identical. The owner's personal pattern (`**/.claude/settings.local.json`) also matches
nested copies, but troupe has only the root `.claude/`. A broader pattern would differ from the website for no
present need.

**D4. Prove the diff by regenerating, not by reading.** After `openspec update`, the diff must touch only the 9
files, and running it again must change nothing. The website is still on 1.14.2, so its copies can't be the
reference. Instead the result is compared byte for byte with a preview generated by the same pinned version in a
separate scratch repository. Any difference stops the change and is reported, not edited away.

## Risks / Trade-offs

- [`openspec update` touches a file outside the expected 9, such as `openspec/config.yaml`] → task 1.2 checks
  `git status` against the expected list. Revert any extra file and report it. None was touched.
- [troupe runs 1.14.3's instructions while the website and infrastructure run 1.14.2's] → accepted by the owner.
  Each repository moves in its own pull request (proposal, Impact).
- [The installed CLI (1.14.2) is older than the skills (1.14.3)] → the skills call `openspec status`,
  `instructions` and similar commands. The only fields 1.14.3's new text reads, `changeRoot` and
  `resolvedOutputPath`, are already in 1.14.2's JSON (seen while planning this change). The CLI itself wasn't
  compared. Homebrew's upgrade removes the gap.
- [The full check (~4.5 min) runs for a change no gate reads] → accepted. See Non-Goals.
